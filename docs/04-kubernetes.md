# 4. Kubernetes

`deploy/k8s/` is plain YAML assembled by **Kustomize** (`kubectl apply -k deploy/k8s`). No Helm:
every object is readable as written.

## One object per need

| Need | Object | File |
|---|---|---|
| a database that keeps its disk and its name | **StatefulSet** + PersistentVolumeClaim | `postgres.yaml` |
| stateless services you can scale | **Deployment** + **Service** | `api.yaml`, `worker.yaml`, `web.yaml`, `redis.yaml` |
| exactly one instance, never two at once | Deployment, `replicas: 1`, `strategy: Recreate` | `ingestor.yaml` |
| a job every 5 minutes | **CronJob** | `reverts.yaml` |
| one entry point from outside | **Ingress** | `ingress.yaml` |
| settings | **ConfigMap** (generated by Kustomize) | `kustomization.yaml` |
| passwords and API keys | **Secret** | `kustomization.yaml`, `make k8s-secrets` |

Things worth noticing:

- **Probes.** The API's *readiness* probe calls `/api/health`, which checks Postgres and Redis.
  Until it passes, the Service sends the pod no traffic. The *liveness* probe restarts the pod if
  it hangs.
- **Requests and limits.** Every container declares what it needs, which is how the scheduler
  packs pods onto nodes.
- **`$(POSTGRES_PASSWORD)` inside `DATABASE_URL`.** Kubernetes expands one env var inside another,
  so the password lives only in the Secret.
- **Generated names.** Kustomize appends a content hash to ConfigMaps and Secrets, so changing a
  setting rolls the pods automatically.

## Try it locally (OrbStack)

```bash
orb start k8s          # OrbStack's built-in single-node cluster
make k8s-deploy        # build images, create the key Secret from .env, apply, wait
make k8s-status
make k8s-open          # http://localhost:8081
make k8s-scale N=5     # watch the new pods join the Redis consumer group
kubectl -n arxiv-classifier delete pod -l app=worker   # kill workers; Kubernetes replaces them, XAUTOCLAIM recovers their edits
```

OrbStack's Kubernetes uses your local Docker images directly, which is why the manifests set
`imagePullPolicy: IfNotPresent`.

## Deploy on a real server (k3s)

[k3s](https://k3s.io) is a full Kubernetes in a single binary, with the Traefik ingress built in.
On an Ubuntu server:

```bash
curl -sfL https://get.k3s.io | sh -                  # install
sudo cat /etc/rancher/k3s/k3s.yaml                   # kubeconfig: copy to your laptop, set server: to the server's IP

# Get the images onto the server. Either push them to a registry and set `images:` in kustomization.yaml…
docker tag arxiv-classifier:latest ghcr.io/<you>/arxiv-classifier:latest && docker push ghcr.io/<you>/arxiv-classifier:latest
# …or copy them directly:
docker save arxiv-classifier:latest arxiv-classifier-web:latest | ssh server sudo k3s ctr images import -

make k8s-secrets && kubectl apply -k deploy/k8s
```

Point a DNS name (or `/etc/hosts` for `arxiv-classifier.local`) at the server and Traefik routes it to
the `web` Service. To add HTTPS, install cert-manager and add a `tls:` section to the Ingress.
